# 第三款小遊戲設計計劃書：街角拾荒

狀態：可交付實作的原型設計基線；已有寫實像素美術規格及本機互動 Demo，正式遊戲、量產美術與玩家測試尚未完成。\
暫名：**街角拾荒**（可再命名；主角為在街頭生活的拾荒者）。\
產品方向：原創的單人合併、探索與街坊訂單遊戲；參考合併物件與委託的通用玩法，不複製任何既有遊戲的角色、物件、美術、訂單或關卡內容。

## 1. 設計目標與原則

玩家透過觀察環境、撿拾與整理物品、使用不同取得物資的方式，完成街坊委託並改善主角的生活。棋盤負責收納整理與配方製作；各生產器提供不同的操作體驗；訂單與人物故事說明物品為何重要。

本遊戲區分兩種操作：**散料打包成收納材料束，以及跨材料配方加工。**首版不自動堆疊獨立物件；同類材料仍逐件保存。收納材料束只適用於白名單上的同類散料，只節省棋盤格位，拆包後原料總量、來源與品質完全相同；不得提高材料等級、功能或價值。涉及結構、功能或品質改變的階段仍須配方。碎木片不能只靠打包變成木條：必須加膠料壓合；木條須加釘件固定才成為承重木板。每項打包規則與配方都要明確標示，不能讓玩家靠猜。

核心原則：

1. **生產器不退休**：新章節為舊生產器增加配方、用途或改良方式，不以新機器直接取代舊機器。
2. **生產網互相供料**：不同來源的物品可進入其他生產器配方；同一物品有多個合理用途。
3. **有依賴、無軟鎖**：跨生產器物品是效率或配方選擇，不可成為唯一且耗盡的啟動條件。每條必要流程都有替代來源、初始供應或可重複取得途徑。
4. **不同來源有不同操作**：尋物、釣魚、分類、修補、料理不是五個換皮點擊按鈕，而是各自有短而清楚的玩法。
5. **離線可玩**：已安裝的核心遊戲與內容離線可用；時間型恢復須以最後保存狀態安全計算，不依賴即時連線。
6. **尊重主角處境**：困境不作笑料，也不把主角的價值簡化為累積財富；成長包含安全、選擇、技能與互助。

## 2. 核心循環

```text
查看街坊委託
  → 準備背包空間與出門用品
  → 選擇合適的生產器與取得方式
  → 探索／釣魚／整理／修補／料理
  → 將成果帶回地盤，收入倉庫／棋盤
  → 在棋盤合併物品或投入配方
  → 交付委託、取得報酬與人物進展
  → 改善生活環境並解鎖新地點、新配方
  → 舊生產器加入新用途，回到委託
```

委託分為三類：

- **日常需求**：食物、可用容器、修補用品等；重複出現，讓早期生產器保持用途。
- **人物／章節委託**：推進角色關係、地點整理與故事，不以單一高階物件無限卡關。
- **生產器專門委託**：鼓勵使用不同來源及交叉配方；允許玩家選擇數個可行需求，不強迫同時追逐所有委託。

報酬包含生活用品、工具零件、街坊信任、棋盤空間或新地點權限。貨幣可以存在，但不是唯一成長指標。

### 訂單、章節與玩家回流規則

- **章節委託**推進主線，一次顯示一個主要目標與最多兩個可選子目標；需要的材料須能在目前已解鎖內容中取得。未達條件時提供「去哪裡取得」提示。
- **街坊委託**是可選、可替換的循環需求，不設到期時間。玩家可拒絕或暫停；拒絕不扣信任、不降低故事評價，也不會移除主線需要的物品。
- **生產器委託**聚焦玩法本身，例如分類一批材料、完成一次釣魚或修補一件物品；不能要求連續成功或特定隨機詞條。
- 首版同時顯示 1 個主線與 2 個循環委託。達上限後可先完成、放入稍後清單或免費替換一般委託，不能因接取而鎖住主要玩法。
- 訂單交付前顯示投入物、報酬、品質要求及是否消耗物件；交付後以逐項清單說明物品去向。品質加分委託不得是主線唯一解。
- 玩家離線期間不累積限時壓力、不發生需求惡化，也不因回來得晚而失去故事機會。重新回來時以「上次進度摘要」提示可續做的主線和可選玩法。

## 2.1 體力、政府救助便當與離線恢復

體力是安排探索行程的節奏工具，不是要求玩家每天報到的計時器。依目前玩家選擇，體力在外出探索的**每一步移動或每次明確互動**時消耗；單純看地圖、讀線索、取消選擇、棋盤整理與合併不扣體力。每個路線節點在行動前顯示成本，玩家可在未確認前改道或返回。體力會在遊戲關閉時照常自然恢復，直到上限；每步成本、上限與恢復速度採第14節初值，後續以玩家測試調整。

### 政府救助的取得與停止

- 主角尚未達到故事中的「生活逐漸穩定」門檻時，每經過一個完整的 24 小時離線／遊戲時間週期，取得一份政府救助便當。資格與故事進度掛鉤，不要求連線或當日開啟遊戲。
- 救助便當累積在本地救助信箱，沒有領取期限、連續登入獎勵或漏領懲罰。為避免玩家長期未開啟而累積大量待領項目，信箱最多逐份保存 7 份；超過容量的每日救助保存為相同恢復價值的整數救助份額，不會因未登入而消失或降低價值。玩家回來時可一次領取或使用。
- 暫定在**階段 5「新街區」的穩定生活章節目標完成後**停止新增救助便當；此門檻代表主角已有較穩定的住處、互助網與可持續收入，不以玩家等級、消費或連續遊玩天數判定。遊戲須提前明示停止條件與剩餘進度。
- 停止新增不會收回已累積的便當或補給。轉換時另提供一次性的 80 點章節補給，讓玩家已有可持續的自選補給途徑；敘事表達為生活支持方式改變，不是懲罰或突然加難度。

### 補給與非強制登入原則

- 便當是可選的體力補給，可由玩家自行決定何時使用，不要求領取後立即消耗；料理台也可用魚獲、可食拾得物與水製作其他補給。
- 政府救助不是體力唯一來源：離線自然恢復持續有效，章節報酬與料理提供額外選擇。救助停止後仍能正常遊玩，不得以此封鎖主線或迫使玩家每日登入。
- 不設每日限時訂單、登入連續天數、過期食物或錯過日子的懲罰。離線經過時間只計算已獲得的救助與自然恢復，不讓離線期間發生體力超額消耗、物品腐敗或進度倒退。
- 離線進度由本機保存的時間戳與已累積份數計算；重新開啟時按經過時間補算，無網路亦可完成。時間回撥或裝置時間異常時採保守校正，不扣除已保存的便當、補給或體力。

救助結束的章節門檻目前是設計提案，應在原型中驗證玩家是否能自然銜接到料理與其他補給；若銜接不順，先調整故事解鎖或提供的過渡補給，不延長每日登入壓力。

## 3. 生產器總覽與解鎖階段

解鎖以章節事件為準，不綁定真實日期或連線活動。階段名稱暫定：

| 階段 | 地點／章節 | 新解鎖 | 對既有生產網的擴充 |
|---|---|---|---|
| 0 | 街角的第一天 | 街頭翻找、起始背包與地盤 | 教玩家辨識可回收、可修補、可食用物件；提供第一批容器、布料、木片及起始收納空間 |

## 4. 生產器、玩法與物品鏈

### 4.0 合併與跨材料製作規則

- **同類合併**：只接受白名單中相同 `itemId` 的材料，可把四份同類碎料整理成「材料束」以節省棋盤格位；首版不另做一般自動堆疊。材料束不提升功能、品質或價值，不可當加工產物使用。
- **配方加工**：物品鏈中凡是涉及壓合、固定、縫製、清洗、烹煮或修補的階段，都必須在指定生產器／工作站加入所需材料。例：碎木片 + 膠料 → 木條；木條 + 釘子束 → 木板（加工來源、品質依投入與操作決定）。
- **多材料製作**：兩種以上不同材料須在配方介面選擇已解鎖配方。介面明示所有投入、產物、可替代材料與解鎖章節；不同材料不能靠直接拖曳而被誤耗。
- **材料束拆裝**：材料束可按原數量手動拆回原材料，保留每件材料的來源、品質、詞條與數量。配方不接受材料束直接作輸入；玩家須先拆包，明確看見每種材料的件數後才能選配方，不能把材料束視為多一份或較高級材料。
- **產物再加工**：加工成品逐件保存，只有白名單散料能打包。下一個結構加工階段仍須配方，不暗中升階。
- **材料束白名單**：布邊料、線頭、碎木片、金屬屑、塑料碎片、紙屑六種，各四份打包為 1×2。金屬碎片不與金屬屑混裝；拆包逐件保留來源／品質，不平均化。
- **配方替代**：重要主線配方至少提供一種替代材料組合，或提供該材料的可重複來源。替代配方可較慢或耗用更多常見材料，但不能要求另一個尚未解鎖的高階產物。
- **配方發現**：主線必需配方以藍圖或明確提示教學；可選配方可從人物互動、試作紀錄或收藏解鎖。未知配方只允許安全試作或預覽，不會要求玩家盲投稀有／主線材料；若試作涉及消耗，先明確展示失敗時輸入物去向。

### 4.0.1 拾得成品、加工成品與品質來源

翻找可能直接找到已經是成品的材料，例如完整木板；它不必先拆成碎木片再重新加工。拾得木板與加工木板**是同一種物品、用途完全相同**，差別放在來源與品質資料上，不拆成不同物品類別：

| 物品 | 來源標籤 | 品質／狀態 | 可用規則 |
|---|---|---|---|
| 木板（拾得） | 街頭翻找、拆卸物；`itemId: wood.board` | 品質可能是受損、普通或良好；保留原有磨損 | 與加工木板完全相同用途，可用於相同訂單與配方 |
| 木條 | 工作台加工：碎木片 + 膠料 | 品質由投入材料與製作結果決定 | 可加工成木板，或分支製作工具柄 |
| 木板（加工） | 工作台加工：木條 + 釘子束；`itemId: wood.board` | 同一物品種類；標示加工來源，基礎品質平均略低於完整原板，但詞條可強化特定性能 | 與拾得木板完全相同用途；品質可影響耐用度或加工結果，不限制基本用途 |

- 物品檢視卡顯示**來源與品質**，例如「木板｜來源：街頭翻找｜品質：普通」和「木板｜來源：工作台加工｜品質：良好」。名稱與用途相同，讓玩家一眼看出來料方式不同。
- 兩種來源使用相同 `itemId: wood.board`，所有一般木板訂單和木框配方都接受兩者；來源不作為配方門檻，也不限制玩家怎麼使用。
- 品質不等於稀有度：完整拾得木板的整體品質平均較好；由碎料膠合、釘接而成的木板，整體品質平均略差，但個體結果會受投入料況與製作表現影響。良好加工板仍可能勝過普通拾得板。
- 品質只影響耐用度、加工成品表現或額外收益，不剝奪基本用途。若委託特別要求品質，須明示品質條件；一般木板訂單不區分來源。
- 餐點是明確例外：品質除訂單／風味表現外，也會影響體力恢復；每道餐有正值的基礎恢復量，品質加成在成品卡顯示，最低品質不得變成零補給或負面懲罰。
- 翻找到成品是額外捷徑和驚喜，不得成為主線唯一來源；加工鏈仍可從常見碎木片與可重複取得的膠料完成。

### 4.0.2 材料正／負詞條

品質描述整體等級；**詞條**則說明這件材料具體好在哪裡、又有什麼代價。詞條不改變物品類別或基本用途，而是影響耐久、支撐、重量、防水或加工效率等明確數值。

| 木板例子 | 來源 | 詞條 | 效果例 |
|---|---|---|---|
| 木板 | 翻找所得 | **裂痕**（負面） | 耐久較低；仍可放進木框、避雨設施及一般木板訂單 |
| 木板 | 翻找所得 | **乾燥穩固**（正面） | 支撐力較好；拾得板也可能達到加工板的效果 |
| 木板 | 翻找所得 | **受潮**（負面） | 暫時降低黏合效果；乾燥後可恢復，不永久報廢 |
| 木板 | 工作台加工 | **膠合牢固**（正面） | 加工成木框時提升接合耐久 |
| 木板 | 工作台加工 | **釘固加強**（正面） | 支撐力較穩定；與拾得板用途相同 |
| 木板 | 工作台加工失手 | **切面粗糙**（負面） | 加工精度或耐久略降；可打磨修復，仍可照常使用 |

整體平衡基線：完整拾得木板通常保有較好的整體耐用度；加工木板平均略差，反映接縫、釘孔與材料拼接造成的折損。但加工木板可能有「膠合牢固」提高接合性能、「釘固加強」提升支撐力或「防水封邊」提高耐候性，因此會在特定用途上勝過原板。原板也可能受潮、裂損或翹曲。這是平均傾向，不是「拾得必勝」或「加工必差」的硬規則。

詞條系統的邊界：

- 每件材料最多顯示 **1 個正面 + 1 個負面詞條**；一般素材多數沒有詞條，避免棋盤變成大量數值管理。
- 拾得詞條依地點、物件狀況與可見線索產生；加工詞條由投入材料與小玩法結果決定。結果在取得／製作完成時立即顯示，不設隱藏隨機懲罰。
- 配方仍接受同一物品種類的不同詞條版本。輸出詞條依配方明確規則承接、抵銷或轉換，不讓加成無限制疊加。
- 負面詞條可透過乾燥、打磨、清洗或修補處理；主線不要求抽到特定正面詞條，負面詞條也不會讓物品失去基本用途。
- 訂單一般只指定物品種類；詞條／品質要求只用在清楚標示的加分委託或可選目標，不暗中拒收同用途材料。

### 4.1 街頭翻找（階段 0）

最主要、永遠可用的供應來源。固定素材調查支持可規劃的補料，驚喜調查可找到完整原生材料。玩家比較用途、品質與占格，決定保留、放棄或回家加工；不在撿起時自動拆成碎料。每步移動／互動消耗、掉落權重及最差保底見 14.1–14.2。

### 4.2 回收分類台（階段 1）

四類分類是辨識與整理，不是憑空升階。分類完成後明確選擇拆線、調膠、清洗或其他已解鎖加工。可完整保留可用物件；失敗不能把已確認的全部物資抹掉。後期供線、膠、包材及新區委託，不被工作台取代。

### 4.3 舊碼頭釣魚（階段 2）

讀魚訊、選餌、控制張力。基本竿、免費餌與連敗引導保底確保可啟動；加工餌與升級釣具提供收益或容錯，不鎖主線魚種。釣魚長期連回料理、魚骨工具、魚貨訂單與水岸材料；已使用餌料在脫鉤時也消耗，不能以稀有度例外退款。

### 4.4 修補工作台（階段 3）

配方介面統一選個別材料，實際操作由配方決定。第一次手動、熟練後可快速；首版手動品質加成與替代配方提供選擇，不另啟用沒有數值定義的「省料／輕便」按鈕。工具、容器、棚架、箱櫃與背包配方見第 13 節。

### 4.5 便攜料理台（階段 4）

食材、水、燃料與容器各自有明確用途；魚與素食兩路都能完成主線。餐點恢復由品質決定，不設飢餓、腐敗或離線降級。煮水、蒸餾、料理與炭爐不是同一個點擊收取動作；各有獨立操作與失敗結果，見第 12 節。

### 4.6 生產網與操作節奏

每個生產器均採「看需求 → 選材料／地點 → 預覽成本與去向 → 短操作 → 檢視品質／副產物 → 收納或交付」。體力只用於探索與採集；加工耗對應材料，不另收探索體力。短操作 6–15 秒，隨時可保存離開，不要求連續上線。來源、品質及加工履歷隨物件保存；熟練、箱櫃和容器都不跨遊戲共用。

### 4.7 玩家資訊與容錯狀態

- 材料卡固定排序：名稱 → 來源 → 品質／詞條 → 數量／耐久 → 可用配方 → 拆解結果。主線需要物件以標記提醒，不鎖定或阻止玩家自行使用，但拆解時再次提示。
- 配方卡固定顯示：可做／缺少哪些材料、可替代材料、消耗數量、輸出預覽、品質承接規則、操作預計耗時，以及取消是否安全。
- 加工開始前預留所有結果所需空間，不另開無限產物暫存；返程暫存及待領教學獎勵依各自容量規則。提供整理建議與來源捷徑，不自動丟棄物件。
- 撤銷、棋盤尺寸、暫存容量及行動成本依第11–14節與實作任務書；首版無站點冷卻。數值集中在ruleset，不散落硬編碼。
- 對色覺差異使用圖示／文字標籤，不只用顏色區分材質或品質；所有拖曳操作提供點選替代方式，操作小遊戲可設定簡化／跳過。

### 4.8 外出背包、地盤與長期倉儲

背包與地盤倉儲是兩種不同用途的容量，不互相取代：背包限制每趟探索／小遊戲可帶回的物品；地盤上的儲物空間保存累積物資，避免每趟都被迫立即加工或交單。兩者均離線有效、物品不腐敗、不因久未登入而清除。

#### 背包（外出攜帶）

- 背包採**格位制**。每件物品有 `packSize`；一般小物佔一格，特大物品佔多格，同類散料可按白名單束裝節省格位。玩家不需管理重量值；物品必須放入連續空間，可旋轉 90 度，空格總數足夠不代表放得下。出門前在準備畫面查看空位、已帶物品及預計使用的魚餌／工具，並選擇攜帶物與空間配置。
- 探索、釣魚等活動取得的可帶回物品先放入本趟背包；稀有／任務物品也佔容量，不能無限直送倉庫，以保留「要帶什麼回家」的選擇。
- 背包滿時，停止新增戰利品並顯示物品清單；玩家可原地整理材料束、放棄普通物、替換低價物或結束本趟。已選擇帶回的物品不可被系統自動丟棄。
- 結束活動後顯示帶回預覽，確認後才轉入地盤收納；如地盤也滿載，該趟物品暫留在「返程暫存」中，直到玩家安排位置。返程暫存最多保留一趟完整背包內容，無期限；處理前可以整理棋盤與倉庫，但不能再開新一趟外出，避免暫存變成無上限倉庫，同時不會丟失戰利品。
- 背包升級透過章節、街坊委託或可製作的袋子增加容量；容量升級只減少整理壓力，不提高掉落品質、不增加體力或稀有物品機率。
- 起始背包由階段 0 劇情提供；第一個可製作升級袋暫定為「拼接布 + 綁帶 + 線團 → 修補背包」，於階段 3 工作台解鎖。升級時背包內物品原位保留，只替換容量參數；玩家不必消耗舊背包或清空內容。

#### 地盤與箱櫃（長期收納）

- 地盤是可擴張的安全生活空間。依玩家確認，完成章節任務逐步開放新地塊；地塊面積增加可放置的收納家具位置，並增加一部分基礎置物容量。擴張不要求真實貨幣或每日登入。
- 玩家可以用木板製作可放置、可命名的木箱；木箱是家具／建物，不是消耗品。木板來源不限，拾得木板和加工木板共用 `wood.board`，均可投入箱體配方；箱子品質可影響外觀或耐用詞條，不應讓低品質板失去基本造箱用途。
- 木箱固定用木板4、釘件束2、回收膠1，容量12格；加固箱用空木箱1、木板2、金屬扣2，容量20格。均占家具位1，不另設箱蓋材料，詳第11／13節。
- 地盤容量來源明確拆成「地塊基礎置物量 + 已放置箱櫃容量」。玩家可在地圖上看到哪些地塊已開放、可放置家具的位置及新增容量，不採隱藏容量。
- 箱櫃可分類標籤、搜尋物品、依物品類型排序；物品可在不同箱櫃間移動，批次存放／取出不改變物品來源、品質或詞條。箱櫃損壞、搬遷、地塊改建均不得使內含物品消失。
- 依玩家確認，倉庫物品不能直接被配方扣取；玩家先將材料取到棋盤或背包，再進行製作。取出前顯示目的位置及容量占用，空間不足時拒絕操作但不移動或扣除材料。所有配方只消耗棋盤／背包中已明確選入的物件。

|---|---|---|

## 5. 跨生產器配方網與防軟鎖

主要依賴方向：

```text
街頭翻找 ──→ 回收分類 ──→ 修補工作台 ──→ 改良工具／釣具／炊具
     │               │                │                  │
     ├──→ 魚餌 ─────→ 釣魚 ──→ 魚獲 ──→ 料理台 ──→ 餐點委託
     │                    │             ↑                 │
     └──→ 容器／燃料 ─────┴──→ 回收材料 ┘                 └→ 探索補給
```

依賴規則：

- 起始翻找不依賴任何其他生產器；所有新模組都由可完成的章節任務或初始物資啟動。
- 釣魚有任務提供的簡易竿與低階免費餌；改良竿和特定魚餌只增加選擇，不是唯一入口。
- 工作台所需基礎材料至少能從翻找或回收取得；工作台產出的工具不得成為工作台自身唯一的啟動材料。
- 料理台可用基礎拾得食材或替代燃料；沒有魚仍能完成基本餐食委託，避免釣魚成為料理的絕對鎖。
- 必要任務不要求指定高階隨機掉落；若棋盤空間不足，允許暫存、回收或拆解非任務物件。
- 不同種類材料不得直接因拖曳而消失或合併；跨材料製作只能在配方介面完成，並先顯示消耗清單與結果預覽。
- 同一基礎材料可進入不同配方，但須有用途提示、配方收藏或訂單預告；不能要求玩家靠猜測才知道材料價值。
- 來源不同但用途相同的物件沿用同一物品種類與配方相容性，並保留 provenance／品質差異；只有特別要求品質的訂單才設定門檻，且須明確提示。
- 每個生產器至少支援一種跨材料配方或將副產物回流到另一個生產器；跨鏈連結要形成有意義的選擇，而非單純增加步驟。
- 每個物品在資料表中列出至少一個「訂單／配方／升級／收藏」用途；每個生產器每個主要章節至少保留兩種可行用途。
- 對有耐久的工具提供修理、低階替代方案或可重做來源；不可永久耗盡唯一生產器。

### 配方與物品命名規則

- 穩定 ID 使用小寫英文 namespace，如 `wood.chip`、`wood.board`、`cloth.thread_spool`、`water.filtered`、`meal.relief_box`；顯示名稱可因語系變更，ID 不隨翻譯變更。
- 物件的來源、耐久、品質與詞條是 instance metadata，不另造 `wood.board.found`／`wood.board.crafted` 這類分裂物品 ID。
- 配方只描述消耗與產物；短操作由 `interactionId` 指向獨立玩法定義，確保相同縫補操作可供多個配方重用。
- 玩家確認前不扣輸入；確認後保存並鎖定操作，依第 11.6 節記錄不可逆加工步驟，結算時原子提交消耗、輸出、位置與事件。
- 平衡數值先以集中式參數維護；禁止把體力、掉落率、耐久、產量散落寫死在 UI 或故事文字。

## 10. 決策紀錄、待確認事項與執行門檻

### 已由玩家確認的遊玩規則

- 水與餐點使用可重用容器；內容物與容器一起占格，用完保留原容器。
- 同配方首次手動完成後可快速製作；手動操作保留爭取更佳結果的價值。
- 背包採拼圖式排列：大物需要連續空間，允許旋轉，不只計算空格總數。
- 品質介面採等級與具體效果，不直接展示內部品質分數。
- 棋盤同類操作可以合併成收納型材料束（例如碎料 → 材料束），只節省格位；不得提升材料功能、品質或價值。材料束可拆回原物件，原材料與加工狀態均守恆。木料鏈保持碎木片 + 膠料 → 木條、木條 + 釘件 → 木板。
- 探索移動／互動逐步消耗體力；檢視、改道、棋盤操作不扣體力。精確成本由原型平衡。
- 小玩法失誤成本依加工方式決定：實際被消耗／不可逆加工的輸入依配方失敗結果處理；可重用工具不會被當作消耗品。操作前明示消耗與副產物，主線材料須可重取、替代或回收，確保失誤不造成不可恢復軟鎖。
- 外出背包採格位制，特大物品佔多格；地盤依章節任務擴張；倉庫物品必須先取至棋盤／背包才可加工。
- 餐點品質影響體力恢復；配方基礎恢復量與品質加成分開設定，最低品質仍有正向補給效果，食用前顯示實際恢復量。
- 材料束必須手動拆包，配方不能直接消耗整束；玩家需先看清布片等材料的實際數量。
- 體力每日救助、離線累積、不要求登入、故事門檻後停止新增等原則沿用第 2.1 節。

## 11. 第一輪可執行規格：加工、品質與空間（2026-10-21）

本節將已確認的玩法轉為實作規格；數量、尺寸、品質係數與熟練門檻是**可測試的原型初值，尚未經遊玩平衡驗證**，不是使用者逐項核准的正式數值。完整配方分列第11–13節，維護／拆裝命令另列第12／13／17節；第4節的概念例子不構成額外未列配方。

### 11.1 名稱、用途與解鎖一致性

- 「木料」只作分類標籤，不作可消耗物品；木條、木板、木框各有自己的 ID。「膠合板／黏合板」在本遊戲是木板的加工來源描述，不另立 ID。
- 木框是材料；抄紙模具、直角夾具是可重用工具，不因使用木框外觀而混成同一物品。
- 防水塗料新增 `material.waterproof_coating`，階段 3 起可從修繕區常見補給重複取得；綁帶用於固定，普通回收膠與澱粉糊不負責防水。塗料合成留待後續配方，不作首版必要路徑。
- 容器新增 `container.used_intact`（完整舊瓶）與 `material.glass_scrap`（玻璃碎料）；`container.safe_bottle` 名稱停止用於新配方。破玻璃只回收，不靠包布變成完整容器。此為虛構遊戲分類，不提供現實飲水安全判定。
- 階段 0 提供針具與少量線的教學操作；階段 1 分類台開放拆線、理線、簡易縫補、調膠、打漿與清洗。熱壓塑料、金屬加工、木作及抄紙延至階段 3。
- 階段 2 釣魚教學直接給基本釣具；不要求先完成階段 3 的釣鉤、浮標製作。階段 3 解鎖時直接提供基本夾具、模具及熱源，燃料可由早期拾得紙木取得。
- 階段 4 才開放料理、澱粉糊及煮水；此前基本補水點提供可直接用於遊戲清洗配方的過濾水。礦泉水在首版只由密封瓶／泉點取得，刪除「加礦物包就等於天然礦泉水」的配方；礦物包暫留選用委託用途。
- 所有必要供應點須有固定可重複取得選項，不能只寫「低機率掉落」。第14.2節列明批量／成本；選用驚喜成品不是主線唯一來源。

### 11.2 手動加工與快速製作

- 熟練記錄以 `recipeId` 保存。原型門檻為同配方手動完成一次且產出有效成品；其他配方、取消操作及只有副產物的失敗不計入。
- 製作介面固定先選配方、個別材料與數量，再顯示預計產物、占格、消耗上限、工具需求、品質範圍與失敗產物；不自動從倉庫扣料，也不自動拆包。
- 快速製作使用相同輸入與工具要求，操作修正為零；「基本品質」是這批材料的基準結果，不保證一律升到普通級。快速製作無操作失誤、無手動額外加成。
- 手動製作依操作結果獲得品質修正，失誤按配方表處理。第一輪僅給品質差異，不同時加入未量化的隨機省料；省料型配方必須另列明確分支才可啟用。
- 原型每次製作一份，避免批量副產物與空間預留過於複雜；熟練不等於自動連做。可重用工具首輪不因失誤額外扣耐久，正常磨耗另由工具表設定。
- 點選／簡化操作與拖曳使用同一評分結果集合，不因無障礙設定降低品質上限。略過演出不會自動解鎖熟練。
- 配方內容更新時，只有輸入、操作或主要輸出改變才提高 `masteryRevision` 並要求重新教學；文案／美術／平衡數值更新保留熟練。

### 11.3 品質與詞條的原型計算

- 內部品質 `q` 為 0–100；顯示粗劣（0–39）、普通（40–69）、良好（70–89）、優良（90–100），不顯示分數。卡片顯示實際耐久、恢復量等效果。
- 配方品質基準取各「主材料」按件數加權平均，輔料不加入平均；配方可另列輔料詞條對特定性能的效果。工具不納入材料品質平均。
- 手動評分分為失手／完成／精準，品質修正分別為 −10／0／+8；快速製作為 0。產物品質為主材平均減加工折損再加操作修正，四捨五入並限制在 0–100。
- 再生結構配方（碎木壓條、木條釘板、碎布拼接）折損初值 8；清洗、分離、裝配配方折損 0。反覆拆解／重做不能無成本提高品質：解構輸出品質不得高於原件，且每次不可逆加工都消耗輔料。
- 拾得完整材料原型品質分布：普通占 50%、良好占 40%、優良占 10%；碎料以粗劣／普通為主。這是可調平衡初值，不保證每塊拾得板優於加工板。
- 詞條最多一正一負，逐配方白名單承接，不自動複製所有詞條。木板「釘固加強」只給支撐效果 +10%，「釘固偏斜」只給耐久 −10%；其他材質詞條的觸發、修正與去除規則統一見第17.4節。
- 工具／結構耐久先按品質等級乘 0.85／1.00／1.10／1.20，再套適用詞條，向下取整且至少 1。沒有耐久用途的物品不硬加耐久值。
- 餐點恢復量按配方基礎值乘 0.8／1.0／1.15／1.3，向下取整且至少 1；食用前顯示實際恢復與超過體力上限的部分。餐點基礎值見第12.4節；救助便當固定40，失敗餐固定4。
- 驗證重點：相同輸入與操作產生相同結果；一般訂單接受所有來源與品質；加工品可在個別性能勝出，但不可靠反覆製作免費洗出滿品質。

### 11.5 拼圖背包、取料與拆包

- 原型起始背包 4×4，首次升級為 5×4，在右側增加一欄，原件座標不變。工作棋盤初值 6×6；這些初值仍須測試整理壓力。
- 每物品記錄矩形 `footprint(width,height)`，`packSize` 為面積衍生值而非獨立規則。保存位置、朝向（0／90 度）及容器 ID；不允許重疊、越界或斜放，旋轉不改變物件身分。
- 全部 111 項物品／裝備的明確尺寸見[完整材料字典](third-game-material-catalog.md)，機器可讀資料為 `../design/street-scrap-design.json`。水與餐點內容不另占格，裝備與固定設施不以假 1×1 格表示；新增物品必須明訂尺寸或非棋盤位置類型。
- 工具與餌料佔背包空間；固定站點設施不佔。水與餐點以容器占位，內裝物不重複占格；完整生命週期依第 12 節，喝完或倒出後保留同一容器 instance，不新增空瓶。
- 原型不自動堆疊獨立物件；數量只在清單摘要顯示。六種白名單散料各 4 份可手動包成 1×2 材料束；同 ID 可混不同品質，內部逐件保存，不平均、不洗詞條。
- 打包時先模擬移除四份材料再放材料束；拆包時先模擬移除束再放四份材料。只有全部放得下才提交；不夠時提供預覽與取消，不扣料、不部分拆包。
- 可以先移動、旋轉其他物件，再按確認；提供點選物件→旋轉→選格的非拖曳操作。系統提供排列建議但不未經確認重排背包。
- 倉庫取料也要預覽合法位置。倉庫以容量格數管理而不要求拼圖；背包與工作棋盤採空間放置。原型木箱容量 12 格、佔地家具位置 1 個，品質不縮減容量；地塊基礎容量與家具位數由章節表另列。
- 返程暫存不算永久容量，最多一趟，不因離線過期；清空前不能再出發。可從中逐件取到背包／棋盤，不能直接作配方輸入。

### 11.6 加工交易、中斷與滿載處理

1. 選料階段只預覽，取消不扣料。開始前模擬移除輸入、放入所有可能結果（含副產物），每個結果分支都須有可行放置；否則先整理，禁止靠製作額外開暫存。
2. 確認後以唯一 `craftOperationId` 保存配方版本、輸入 instance、工具、預留位置及操作進度；輸入鎖定，不能同時交單、打包或轉移。
3. 尚未做不可逆動作可取消並解鎖輸入；進入剪切、混合、燃燒等步驟後，不允許免費退料。離開畫面保存操作，重開可續做，或確認按該步驟的失敗分支結算。
4. 結算一次性提交消耗、產物、副產物、熟練與位置；重複按鈕或恢復事件以操作 ID 去重，不再扣料、不再產出。
5. 品質結果在結算前不公開可重抽的隨機值；原型計算為確定性。恢復時使用已保存的配方版本，不用新版本規則重算進行中的加工。
6. 存檔失敗時不顯示已完成，保留最後有效存檔與待完成操作供重試；不得清除輸入後再單獨寫產物。箱櫃放置或背包升級也走同一原子交易。

## 12. 水、容器與餐點的完整生命週期

### 12.1 可重用容器模型

使用者已確認容器要保留並重用。以下容量、數值與操作時長是原型初值。此節取代早期「每份水單獨一格」或「清潔容器是消耗材料」的概念簡寫。

- `containerInstance` 保存唯一 ID、容器種類、來源、品質、詞條、所在格、清潔狀態與可選 `contents`。內容保存水／餐點 itemId、份數、品質、詞條與來源紀錄，不另生成可獨立移動的棋盤物件。
- 首版瓶／罐均為 1×2、容量 1 份；餐盒為 1×2、容量 1 份；保溫餐盒同容量與尺寸。不實作半份水、不同水混合、大桶或自動跨瓶湊量。一次配方需要水 2 份時，玩家選兩個裝水容器。
- 完整瓶／罐可裝任一水種；餐盒只裝餐點；木箱不裝液體。空瓶占位與滿瓶相同，不可用喝水免費壓縮空間。
- `container.used_intact` 是未清洗完整瓶的內容定義；清洗後顯示「清潔瓶」，保留 instance ID 和尺寸。`container.clean`／`container.clean_jar` 是瓶／罐的清潔形態，轉換不新建第二件容器。餐盒另保留其形態 ID，清潔度用狀態表示。
- 清潔狀態為 `clean`／`utility`／`soiled`：空乾淨瓶可裝料理用水；裝濁水、泥水、髒水後成 utility；吃完餐點的餐盒成 soiled。裝不同用途前依配方洗淨；遊戲用清楚圖示判定，不要求玩家判斷現實飲水安全。
- 水的污染處理史是內裝物狀態，不因換瓶、品質等級或加礦物詞條而被清除。第一版有 `requiresBoiling` 旗標：由髒水過濾得到的水仍須煮沸；補水點的可料理水不帶此旗標。
- 沒有常溫／冷卻倒數：開水表示「已煮沸的水」，不代表永遠燙熱；第一版餐點均按食用時計算品質恢復，不因離線變冷扣恢復。保溫餐盒在特殊委託提供包裝加分，不增加無限可疊的體力加成。

### 12.2 容器操作與去向

| 操作 | 前置與耗用 | 完成結果 | 滿載／取消規則 |
|---|---|---|---|
| 裝水 | 一個空且相容的容器；選一種水源 | 原容器增加 1 份內容；來源寫入內容記錄 | 容器原位，不新增占格；未確認不扣採集成本 |
| 倒到另一瓶 | 來源有 1 份，目標空且符合清潔要求 | 內容移入目標；來源變空，來源身份保留 | 不允許混水或覆蓋；兩件容器一次交易 |
| 配方用水 | 明確選裝水容器作材料槽 | 只扣內容；空容器留原位；污水容器仍為 utility | 不能假設輸入水占格會釋放；預留算法保留容器格位 |
| 濾水／煮水 | 原容器與固定工作站設備 | 水倒入站點處理再裝回原容器；需要清潔的接收瓶須另選 | 原容器不消失；多選接收瓶時明示原瓶變空 |
| 飲水 | 開水、無煮沸旗標過濾水或礦泉水 | 內容清空、原瓶保留；首版飲水不回探索體力，只有餐點補給 | 顯示「不恢復體力」並可取消，不引入飢渴值 |
| 吃餐 | 一份已完成餐點 | 體力恢復，原餐盒變空且 soiled；不返還新餐盒 | 體力已滿時禁止誤食；部分溢出須確認後才消耗 |
| 清洗 | 空容器 + 過濾水 1 份；水無 requiresBoiling | 將目標容器設 clean，水來源瓶變空；兩者都保留 | 目標不能是供水瓶本身；在補水點可直接付採集成本洗瓶 |
| 裝餐 | 空 clean 餐盒 + 待完成料理 | 產物填入選定餐盒，容器保留自己的來源與品質 | 未選好餐盒不能開煮，不新增無限料理暫存 |
| 普通食物訂單 | 玩家選符合需求的裝餐容器 | NPC 收餐點，當場返還同一個空 soiled 餐盒 | 交付預覽只標扣內容；回傳不需要額外位置 |
| 明示包裝訂單 | 需求明列餐點及指定包裝，玩家確認 | 內容與容器一併交付，報酬包含包裝成本 | 普通主線不強制消耗唯一容器；列為可選委託 |
| 丟棄內容 | 二次確認，顯示失去的內容 | 只清除內容，容器按原清潔狀態保留 | 不創造副產物，不改品質；丟棄容器另走獨立確認 |

起始教學提供 2 個完整瓶；階段 4 提供 1 個餐盒。公共補給點直接提供兩項操作：清洗空容器、替清潔空容器裝入過濾水；各耗 2 體力，裝水不另產生一格散裝水。玩家不用先持有水瓶才能清洗第一個回收瓶。空瓶可於街頭固定容器角以一次互動取得，不靠隨機保底；補給點亦保留固定容器來源作為後續補充。

### 12.5 物品流與中斷驗收增補

- 裝滿→倒水→用水→再裝水→重開，任意次數後容器 instance 總數不變；只有明示取得、造箱以外的容器製作、回收或包裝交付才能改變容器數。
- 來源瓶倒入目標瓶時品質與污染史一起移動；不能靠倒瓶清除 requiresBoiling 或提高品質。
- 用水配方的源瓶不釋放格位；泥料、魚骨、失敗餐等所有結果必須事先有位置或餐盒，未足夠就不能開始。
- 髒水濾成水後仍不能料理；煮沸失敗不清除旗標；成功一次後存檔恢復不重複耗燃料。
- 普通餐單返還原餐盒，包裝訂單消耗餐盒，兩者預覽與實際事件一致；雙擊交單不複製容器或獎勵。
- 工具、濾布、容器與內容的品質是不同欄位：換高品質瓶不會提高水品質；容器品質不乘餐點恢復量。

### 13.3 耐久、修理與設備用途

- 針具是教學永久工具，不磨耗；玩家不能把唯一針具交給消耗型訂單。抄紙模具與固定站點工具不磨耗，不引入額外資源瓶頸。
- 簡易釣竿基礎 20 次、修補釣竿 30 次、改良竿 40 次；撬具及分類鉗各 30 次；修補錐 20 次。總次數再按第 11.3 節品質／詞條計算，最少一次。每次實際使用扣 1，取消預覽不扣；失誤不額外磨耗。
- 耐久歸零的工具保留實體，停用其加成，不刪除物品。碼頭可免費借用不佔攜帶欄的固定入門竿，操作不享升級容錯；因此釣魚不會被修理資源封鎖。
- 工作台修理：釣竿用備用釣組 1 恢復 10 次；撬具／鉗用金屬碎片 1 + 綁帶 1 恢復 10 次；錐用金屬碎片 1 或魚骨 1 恢復 10 次。不得超過原最大值；滿耐久不接受修理，不提高品質。
- 金屬工具精密保養（階段 5）：蒸餾水 1 + 布邊料 1 可取代一次金屬工具修理配方，恢復 10 次；消耗水不消耗容器。礦物包 1 + 泥料 2 可交「修補牆面」重複委託，供特殊水副產物穩定出口。
- 木箱／背包／地塊不設日常磨損，避免低品質使容量突降或離線遺失；其品質只反映可選交付價值、外觀與收藏。撬具加成是解鎖額外搜尋選項，不減主線必需體力；分類鉗是操作容錯，非被動倍產。
- 拆解可攜工具預覽只回收 1 份金屬碎片（木柄工具再給木屑 1），不按原配方全額返還；工具組拆回原子工具與原耐久，不能藉拆裝修理。已有內容的容器、箱櫃與套裝先清空或選定合法接收位置才可拆。

## 14. 生產器操作與章節經濟初值

### 14.3 體力、交換券與救助

- 初始／上限體力 60；每 5 分鐘自然恢復 1。離線按完整分鐘補算，保留不足 5 分鐘的餘額；達上限後不累積隱藏體力。空間整理、站點加工與返程均不扣體力。
- 每個主線任務首度完成回復 10 體力，不超上限；若將溢出，剩餘回復額存為一次性「章節補給」數值，可稍後領取，不占棋盤、不自動轉成物品。重播已完成任務不重發。
- 每份救助便當基礎恢復 40，固定普通品質。信箱最多顯示 7 份，溢出以同額的「救助份額」整數保存，每份仍能恢復 40，不轉成品質／價格不明的食材。使用從信箱扣一份，政府回收餐盒不進玩家物品庫，因此不能刷空盒。
- 救助起算點為建立存檔時，初始先給 1 份，再每滿 24 小時新增 1 份。時間回撥不重發，恢復到先前高水位時間後才繼續計算。裝置大幅快轉不能在純離線設計中可靠防作弊；記錄異常，不刪既有物品，不宣稱具伺服器級防作弊。
- 階段 5 穩定生活完成時，先按完成時間結算已有救助，再停止新增；發一次章節補給 80，庫存和份額保留。階段 4 開始預告、階段 5 完成前再次確認，不突然中斷補給。
- 交換券不可購買、不可玩家交易；用途為可選外觀與收藏展示（每件 20 張），無主線必需材料或救助資格門檻。普通循環訂單依表固定發券，品質不影響主線報酬；選用良好品質訂單額外 +2。
- 原型同時顯示 1 個主線與最多 2 個已解鎖普通循環單；可免費替換其中一張為下一個可選循環單，槽位與輪替游標存入本機存檔，離線重開不洗牌。替換不扣物品、交換券或信任，也不會清除其他槽位；完成循環單後保留原卡，玩家可自行決定是否替換。候選不足時不補造虛構訂單，且不可替換的按鈕停用。信任僅由主線旗標決定解鎖，不另刷經驗等級。

### 15.2 字典補足的終端功能

- 簡易浮標可放入釣點裝備槽（最多 1 個），僅對基礎竿擴大容錯區 5%；與修補／改良竿取最大加成，不累乘。製作時空清潔瓶以子物件形式鎖入浮標，瓶子的 instance ID、來源、品質與詞條均保留；拆解返還原瓶但不返還已消耗的粗繩。
- 小型浮架放在碼頭設施位（固定 1 位，不吃地盤家具位），開啟浮架釣點；失敗副產物可選魚骨 1 或漂木 1，不提高必得魚機率，也不要求主線先造浮架。收回時須有 2×2 空間。
- 外出料理組提供可選炊具交換委託：階段 5 交 1 套得 10 券；首次取得記收藏。首版不額外實作野外料理，此物品仍有具體加工與交付用途。
- 失敗餐的回收單一次 3 份換 1 券，只扣內容並返還原餐盒；也可自用恢復 4。這是獨立餐食回收入口，不將餐盒當普通碎料消耗。

### 15.3 證據邊界與下個完成門檻

目前通過的是靜態設計資料檢查，**不是遊戲 runtime、實際操作手感、完整物料數量守恆或經濟平衡測試**。定性可達性忽略數量、容器清潔、背包排列、失敗消耗與耐久；宣告終端用途只證明企劃有規格，不證明功能已做。

數量與容器約束的首批試算已見第 16 節；新手／熟練／離線回流腳本、畫面與狀態轉換、實作依賴及完成標準已整理於[實作任務書](third-game-implementation-taskbook.md)。第17節及配方policy已明列主材、操作評分與身分規則；最終交付稽核見設計完成查核表。灰盒玩家觀察與真機 QA 屬未來實作交付門檻，不得為了完成企劃而虛報已執行。

## 16. 數量、容器與空間的設計試算

從 game package 根目錄執行 `npm run design:simulate` 可重算；對應 owner 測試為 `tool/test/street-scrap-scenarios.test.mjs`。試算從現有配方表讀用量、從遊戲 package 設計資料讀供應量與成本，不另抄一套配方數量。

| 情境 | 初始條件 | 計算結果 |
|---|---|---|
| 碎料做木板 | 階段3、體力60、乾淨空瓶1；分批拿紙／膠／碎木，使用過濾水代替濁水；公共水槽洗瓶2次 | 13 次供應、40 體力（含洗瓶4）、10 次加工，剩體力20；得木板1，原瓶仍在但為待清洗；工作棋盤最高占10格 |
| 同餐盒做兩份基礎湯 | 階段4、體力30、乾淨瓶2與餐盒1；正常品質／正常完成；吃第一餐後洗盒再做第二餐；公共水槽洗瓶2次 | 野菜2、過濾水4、燃料4；採集與洗瓶耗27、恢復40，結束體力43；原兩瓶與餐盒均保留、最後待清洗；棋盤最高10格 |
| 第一份湯失手再做第二份 | 與上一情境相同；第一餐失敗、第二餐正常 | 投入及採集／洗瓶耗用相同；恢復4+20，結束體力27；不是失敗退料，也沒有新增空盒 |
| 14天未登入且仍符合救助 | 新存檔初始1份、未使用任何便當、經過完整14天 | 可見7份＋額外8份權利，共可回復600；體力自然回復至60；不因信箱顯示上限刪除份額 |
| 面積相同但放不下 | 4×4 空包，兩個2×3與一個2×2，允許旋轉 | 面積16仍放不下；把最後物件改為1×4才可放入，不能用面積加總代替排列檢查 |

基礎湯的水正確計量為：清理食材1份＋煮成兩份開水的來源水2份＋中間洗餐盒1份，共4份；煮水後的同一份水進湯，不額外再扣一次水。模型現在採用第12.2節兩個起始瓶，瓶內水被加工消耗後依清潔狀態改為 utility；公共水槽每次清洗一個空瓶扣2體力。兩份湯情境共需洗瓶2次，總耗體力27；首份失手時結束體力27，仍可完成第二份。此為選定流程的資料試算，未模擬移動路線、其他失誤排列、品質或真實存檔／遊玩操作。首次取得／洗淨容器的成本不含在此樣本；情境先明示持有乾淨容器，不能用這些成本宣稱全新玩家從零成本。

檢查器另驗證：缺餐盒時整次加工拒絕且原料不變；瓶已滿時取水不扣體力；體力不足不取得物品；食用恢復不超過上限。工作棋盤使用可重排矩形的搜索模型，來源批量也檢查可放入4×4空背包。**它沒有模擬連續路線的剩餘背包空間、全章節物流、任意失敗序列、工具磨耗、完整品質或實際存檔 I/O**；那些仍由任務書的 production 測試與玩家觀察驗收。

試算顯示木板回收鏈成本高，支持第3章提供原生板做首次木箱的設計；但不據此刪除完整回收路徑。餐食在這個固定供應／正常品質情境能補回採集成本，失手一次後仍可恢復；不代表所有配方、路線與品質都已平衡。

## 17. 配方執行細則與剩餘設計決策

### 17.1 每條配方的明確設定

`../design/street-scrap-recipe-policy.json` 為全部 78 條表列配方提供：工作站、操作類型、操作目標秒數、主材料 ID、加工折損、品質計算模式、需保留身分的輸入及熟練版本。配方表定義數量／失敗結果；policy 定義演算，不允許實作者自行猜主材。這是原型設計初值，production 轉資料時要一併匯入，不能只匯入成功配方。

- `primaryInputs` 是計算品質的材料；其他輸入是輔料，工具另列且不消耗。替代組替換主材時，以選到的替代物繼承同一角色。共享餐採食材與魚肉件數加權；全素替代時四份清理食材都算主材。
- `weighted-primary` 依第 11.3 節計算；`capped-at-primary` 用相同算法但不得超過主材平均；`preserve-primary` 保留主材品質，不因包裝／升級／清洗再加8或減10。多個保留子物件各保留原品質，外層展示件數加權品質，不改子物件。
- `wash_filter` 沒有新物品或品質計算，只改指定濾布次數；洗滌失敗不提高品質。材料拆分的每個副產物採該次結果品質，不把一個高品質原件複製成無限高品質來源。
- 濾布用途次數取第 12.3 節固定值，不再乘工具品質係數；它是特例。釣竿等工具取第 13.3 節基礎值，乘品質／適用詞條。背包、家具容量與瓶容量不乘品質。
- 品質採集取值固定：碎料 q=30／55 各50%；完整材料 q=55／80／95 按50%／40%／10%。不是任意在等級區間重抽。教學獎勵普通 q=55，固定借用竿 q=55。
- 成功且有多個產物時，各份品質依上述算法產生；不能將「每次做一份」誤讀為魚肉2或燃料2只給1。每次只執行一個配方批次，產量仍用配方表數字。

### 17.2 操作模板與評分

原型操作的時間是預計完成時間，不是強制失敗倒數。每個動作可以暫停或改點選；魚訊另按第 14.1 節。每種模板固定三個檢查點，3點合格=精準、2點=完成、0–1點=失手；水處理成功需要至少2點，任何不合格不以品質或動畫跳過掩蓋。

| interaction | 三個具體檢查點（均先顯示目標） | 合格條件 |
|---|---|---|
| sew | 依序穿過三個標示孔 | 每個放點在孔中心半徑12%格寬內；相反順序該點不合格 |
| align | 排齊兩端，再校準接縫／直角 | 對齊標記偏差不超過物件寬度10%；角度偏差不超過10度 |
| strike | 三個釘接／整形落點 | 落點在提示圈內，圈半徑為工作區寬度12%；不以現實力道判斷 |
| heat | 預熱、維持、收火三次設定 | 每次選到已標示的五段火力中目標段；保溫時不需一直按住 |
| mix | 三次配比／濃稠度調節 | 五段滑桿選目標段；不是另加表外材料 |
| cut | 起點、轉折、終點 | 各點在目標區；拆線和切魚依不同輪廓呈現，不要求高速滑動 |
| wash | 找到並清理三個污點 | 每個污點完成覆蓋；漏一點最多普通完成，漏兩點按失敗結果 |
| braid | 左、中、右三次交織 | 按箭頭順序放入指定位置；張力設為提示段，失手不額外無上限補扣線 |
| coat | 左、中、右三區塗層 | 各區至少覆蓋80%，顯示覆蓋量；塗料總耗用固定 |
| filter | 選粗濾層、炭層、接收容器／分層邊界 | 所選層序與提示一致；分水輪廓偏差不超過10% |
| cook | 下料、火力、起鍋 | 依配方提示順序／區間完成，不引入隱藏熟度要求 |
| sort | 三次類別／可用片辨識 | 選對圖文提示；原生分類可立即改正，配方整理則依結果計分 |
| assemble | 底件、連接件、固定檢查 | 三件依影子輪廓定位；彎鉤／套環改用同類三段輪廓定位 |

例外：`recycle_glass`、`salvage_board` 為確認式拆解，不做精準獎勵或隨機失敗；包裝 `toolkit`、`cook_kit`、`fish_pack` 及浮標拆裝只檢查位置，無損壞結果。這些配方第一次確認完成即記熟練。水／料理等不可逆動作在第一個檢查點前保存投入鎖；玩家放棄後按配方失敗結果結算，不依半秒差異猜耗用比例。

### 17.3 身分、升級與失敗優先序

- 表內「消耗輸入」對一般耗材表示刪除指定數量；對 policy 的 `retainedInputIdentities` 表示轉換／包入另一物件，不能刪掉後再生成相同物件。容器內容消耗永遠只扣內容。
- 升級竿、箱櫃、餐盒保留原 instance ID，轉 itemId 並記履歷；工具升級後剩餘耐久按原剩餘比例乘新最大值向下取整（原本0仍為0），不能藉升級白洗滿。箱櫃升級保持容量不縮減，內容按取出規則先安排。
- 背包升級為裝備狀態修改，保留原背包ID及全部位置；不產第二個背包。套裝內部保留每件工具ID、品質與耐久；外層只有一份owner，拆套裝還原原物，不退包材。
- 鍋具與冷凝器以原罐ID轉形態，之後拆解只按工具回收規則給材料，不返還完整罐。簡易浮標以原瓶作受包覆子物，拆回瓶仍為原清潔狀態，不保證憑空洗淨。外出料理組是包裝容器：鍋具與爐架作為兩個不同子物件保留各自身份、來源、品質及詞條；拆包須同時安排兩者空間，防潮包材已消耗，不作為可回收內容。
- 失敗優先序：配方表列出具體失敗輸出時用該分支；否則使用該節通則產出同物品並套−10品質。保留身分／包裝例外不改原品質，失手只顯示需重新定位；定位完成才提交，不額外耗輔料。
- 除餐點的 `meal.failed` 與明列不產主物的分支，低品質成品仍算有效成品並可解鎖熟練。維修、洗濾布與工具拆解不以重複操作提高品質。
- 所有工具拆解排除針具、借用竿及站點設施；針具不能丟棄或交消耗型訂單，避免唯一入門工具消失。完整空瓶可丟棄，但固定容器點可重取。

### 17.4 詞條的可執行邊界

首版採以下有限集合，各材質在解鎖時就可有具體正負詞條；不使用未定義的同義詞條。第4節的「乾燥穩固／膠合牢固／防水封邊」在顯示文案可以描述原物，但只有下表ID參與計算，不偷偷疊第二份加成。

| 詞條 ID／材料 | 觸發 | 精確效果與傳遞 |
|---|---|---|
| `joint_reinforced`／加工木板 | nail_board 精準 | 支撐+10%；裝配木框時可承接，同號只取一份，不按板數累加 |
| `joint_skewed`／加工木板 | nail_board 失手 | 耐久−10%；工具柄／木框若選入此板承接一次；箱子容量不受影響 |
| `clear`／過濾水 | 濾水精準 | mix_pulp 品質+3一次；處理成開水後不再承接此詞條 |
| `mineral_rich`／礦泉水 | 固定礦泉水來源 | 湯品品質+3一次；與固有礦泉風味是同一效果，不雙算 |
| `intact_fibre`／布、線、繩 | 原生良好布料；精準縫補／編繩 | 用於下一個布料或工具配方時品質+3一次；不給包容量加成 |
| `frayed`／布、線、繩 | 拾得磨損；縫補／編繩失手 | 下一個布料或工具配方品質−3；補線修整可去除 |
| `cracked`／原生木料 | 驚喜拾得負詞條 | 製成有耐久工具時耐久−10%；不用在箱子容量；加工成木條／板時可承接 |
| `damp`／木、紙 | 拾得潮濕提示 | 造紙／木作產物品質−3；乾燥處理去除；不禁止作燃料 |
| `smooth_metal`／金屬、零件 | 精準金屬整形 | 下一次金屬工具加工品質+3 |
| `rusted`／金屬、零件 | 拾得鏽蝕提示 | 下一次金屬工具加工品質−3；擦拭去除 |
| `sealed`／塑料、防水布 | 精準熱壓／塗層 | 防水接頭、棚布、袋子製作品質+3；不減占格、不改袋容量 |
| `brittle`／塑料 | 熱壓失手或拾得脆化 | 接頭／浮標品質−3；再次熱壓去除，需燃料 |
| `even_pulp`／紙漿、紙板 | 精準打漿／抄紙 | 下一次紙板／包材品質+3 |
| `rich_ingredient`／魚肉、清理食材 | 精準分切／清理食材 | 料理品質+3一次；不直接乘恢復，避免雙算 |
| `rough_cut`／魚肉、清理食材 | 分切／清理失手 | 料理品質−3；不能修回原始食材，可照常烹煮 |
| `even_burn`／燃料 | 精準燃料整理 | 下一次控火操作的目標區寬度乘1.1；不改燃料份數 |
| `smoky`／燃料 | 乾燥／混合失手 | 下一次熱加工成品質−3；重新乾燥去除，不阻止煮沸成功旗標 |

主材多件有同號詞條時固定按「對當前輸出適用 → 詞條ID字典序」取一個；不可同時套同詞條多份。正負分別最多一個。預覽先列實際採用的詞條，沒有隱藏重抽。去除 `joint_skewed`：階段3工作台以原板+釘件束1修正，普通定位完成即保留原板品質並移除負詞條，不改為正詞條、不返還舊釘；失手原板保留負詞條且新釘消耗。此為維護命令，不計入78條新物品產出配方。

詞條生成：固定供應不抽額外正負詞條，只有畫面已提示的狀態；驚喜物件在類別／品質抽樣後，正面獨立20%、負面獨立20%，各從適用池依ID排序等權選1。沒有適用池就無詞條，不跨材質硬配。加工的普通結果不新增詞條，精準／失手按表新增相應正／負詞條；原輸入詞條只在表列適用輸出承接，新產詞條優先於同號承接詞條。

維護命令明確成本：去 frayed 用原件+線團1；去 damp 用原件+乾燥燃料1；去 rusted 用原件+布邊料1+過濾水1；去 brittle 用原件+乾燥燃料1；去 smoky 用原件+紙屑1。階段3起工作台開放，對應 sew／heat／wash 模板，普通完成即去詞條，保留原品質、ID及數量；失手仍耗輔料但不去詞條。cracked 不能直接消除，須走有損拆解／重製路徑；rough_cut 留到料理，材質變更後不再承接，已計入該次品質折損。這些都是選用改善，不鎖主線。

材料加工品質計算順序固定：主材平均 → 加工折損 → 操作修正 → 最多一正一負的適用詞條修正 → 料理可選調味／水種修正 → clamp。同一加成因固有屬性與詞條重複出現時按ID只計一次。支撐／耐久類不轉成品質修正；沒有該屬性的成品顯示「此用途不生效」，不暗中變更容量。

### 17.5 掉落、任務與固定來源的缺口收束

- 驚喜池以 itemId 明列：常見碎料為 cloth.rag_piece、cloth.edge_scrap、cloth.thread_end、wood.chip、wood.sawdust、paper.scrap、metal.scrap、metal.shard、plastic.scrap；完整基材為 wood.board、metal.sheet、metal.nail_bundle、rope.coarse；容器為 container.used_intact、container.clean_jar；特殊物為 material.waterproof_coating、material.mineral_pack、water.mineral。依字典階段過濾後類內等權。
- 驚喜礦泉水不免費送瓶；顯示水源事件，收取前選空瓶，沒有空瓶可放棄。其他驚喜不從源瓶清潔度推論內容安全；物件來源記為該節點。
- 第一章「完整物」教學接受固定金屬回收架取得的完整金屬片或木板；不要求再次隨機找到原生木板。教學送的木板是捷徑，不是耗盡後唯一達成方式。
- 階段3木條／木板教學若失手，低品質有效成品照算。料理教學若做出失敗餐則不算完成，從固定野菜／燃料／補水點補料再做即可；自然恢復等待屬節奏限制，不稱永久軟鎖。
- 首次拾得完整品可直接交訂單；「加工整體較差」不強迫每個加工個體都輸給原生品。材料先選q=55，普通兩階木作可算出木條47、木板39；精準兩階可保持55；原生完整品平均 q=69，形成平均差異而非硬禁用途。
